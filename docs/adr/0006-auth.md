# ADR-0006: Session auth, optional TOTP, Google as a linked identity only

- Status: accepted

## Decision
Django sessions with CSRF, Argon2 password hashing, DB-backed rate limits, session epoch for global invalidation. TOTP via pyotp with encrypted secrets and hashed one-time recovery codes. Google sign-in uses the authorization-code flow with PKCE, state and nonce; ID tokens are verified with Google's JWKS (PyJWT) for issuer, audience, expiry and nonce; identities are bound by (issuer, subject) with a uniqueness constraint; no auto-linking by email and no registration. App TOTP is still required after Google sign-in.

## Consequences
No third-party auth framework; the flow is small and fully covered by protocol tests with a local key pair. A live Google login must still be verified with real credentials (pending).
